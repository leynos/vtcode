## Problem Statement

VTCode 0.142.5 is configured with an OpenAI-compatible custom provider named
`arli`, but an ACP prompt is sent through the built-in OpenAI Chat Completions
endpoint and fails with HTTP 401. The expected behaviour is for ACP to retain
the startup provider, model, endpoint, and credential identity and send the
request to `https://api.arliai.com/v1`.

## Hypotheses

### H1: ACP lacks boundary-local custom-provider registration

**Claim**: ACP relies on the binary dispatcher's global registration side
effect, so the canonical ACP launch path does not itself establish the custom
provider registry required by prompt handling.

**Plausibility**: High — `run_prompt` resolves the session provider through the
global factory, while registration currently occurs only in the top-level CLI
dispatcher rather than `run_acp_agent`.

**Prediction**: If this hypothesis holds, a minimal ACP-boundary test that
registers an Arli-shaped provider at launch will make `create_provider_with_config`
resolve `arli`; without boundary registration it returns `Unknown provider`.

**Confidence on falsification**: High. Provider-factory lookup is deterministic

### H2: ACP session metadata overwrites startup selection

**Claim**: New-session or restored-thread metadata replaces the configured
`arli` provider with `openai` before `run_prompt` creates its backend.

**Plausibility**: Medium — ACP stores provider and model per thread, although a
new session is intended to seed both from `CoreAgentConfig`.

**Prediction**: If this hypothesis holds, a newly registered ACP session built
from an `arli` core config exposes `openai` in its session data.

#### H2 Falsification Plan

| Step | Action | Expected Negative Result |
| ---- | ------ | ------------------------ |
| 1 | Construct a `ZedAgent` with provider `arli`, register a session, and inspect its provider. | The session provider remains exactly `arli`, disproving metadata overwrite. |

**Tooling**: Focused `vtcode-acp` unit test.

**Confidence on falsification**: High for newly created sessions; restored
sessions would remain a separate case.

## Falsification Result

H1 was **not falsified** with high confidence. A focused, no-network test using
a dummy key showed that an Arli-shaped provider fails factory resolution before
registration and resolves immediately after `register_custom_providers` is
called. The production correction therefore registers
`vt_cfg.custom_providers` inside the canonical ACP launch boundary and retains
that experiment as a regression test.
